## New findings

### N1 - MEDIUM: the account pages do not swap content on soft navigation

`/account/sessions` -> clicking a session's "Revoke" updates the URL and the
document title ("Revoke this session?") but the BODY still shows the sessions
list, so no confirm control appears and the click looks like it did nothing. The
same happens in reverse after the POST: the URL returns to `/account/sessions`
and the title to "Sessions" while the body still shows the confirmation page. A
hard reload renders each page correctly, and the revoke itself works. This is the
documented "a blockless standalone template renders but never lands in the live
DOM" shape (zenit CLAUDE.md, soft navigation) and it makes the account area feel
broken. Expected: the body swaps with the URL.

### N2 - LOW: a long stat-tile label still runs under its icon at 1024

At 1024x768 the dashboard's "Certificates" tile has its label glyph box ending 16px
PAST the icon's left edge (`textRight` 585 vs `iconLeft` 570); "Sites", "Access
lists" and "Active bans" clear it by 35-43px. `pl-stat-card` reserves the icon
lane with `padding-inline-end`, but the label neither wraps nor ellipsizes, so the
longest word overflows into the reserved lane instead of being cut. Expected: the
label wraps or ellipsizes at the reserved edge.

### N3 - LOW: the path browser keeps a stale error and drops focus

Entering a directory the source refuses (`/etc` here) shows "This directory could
not be loaded", and because the failed arm renders no filter input the focus claim
finds nothing focusable and focus falls to `<body>`. Closing and reopening the
picker still shows the error rather than re-listing the root. Expected: a failed
load returns to the last good listing (or re-lists the root on reopen), and focus
lands somewhere meaningful.

### Also observed

  heading and title. Either require the name or derive a friendlier fallback.
- The global rules list empty state says "No **R**ules yet" while the record tab
  says "No rules yet".

## Still open from before

- **13, generic confirmations.** "Delete visual-qa-20260828-acl? This cannot be
  undone." says nothing about the rules that die with it - and since this pass
  proves the cascade is real, the wording is now actively incomplete. Host,
  environment, channel and rule deletes are the same. This is the one finding the
  remediation deliberately skipped and the one most worth doing next.
- The login card is still branded "Zenit": `brand.name` is set in the repo's
  `settings/default.dry` but not in the host's `/opt/hohenheim/settings/`. An
  environment fix, not a code one.
- Activity recording is still off; all six install roles are still enabled against
  a Proxy+DNS deployment; both hosts are still Blocked, so Instances / Stacks /
  Databases / Git providers remain untestable end to end.
