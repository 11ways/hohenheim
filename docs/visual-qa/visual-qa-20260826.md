## Deployment Scope

Source declares six installation roles: Proxy, DNS, Firewall, Stacks, Databases, and Instances. The rendered sidebar exposes role-gated destinations from all six roles:

- Always/system: Dashboard, Projects, Users, Roles, Activity, Notification channels, Settings, Build info.
- Proxy: Sites, Certificates, Access lists, Released hostnames, Git providers.
- DNS: DNS zones.
- Firewall: Abuse protection, IP bans.
- Stacks: Stacks.
- Databases: Databases.
- Instances: Hosts, Instances, Runtime images, Instance templates.

The live deployment therefore appears to have all six roles enabled, not only Proxy + DNS.

Meaningful action coverage still depends on fixtures and safe infrastructure. The dashboard shows two hosts (`local`, `phoenix`), both blocked from placement. Instances, stacks, databases, federation, ACME issuance, and Spamservice runtime coverage will be classified from their actual fixtures rather than from role visibility.

#### F1 - Empty Host picker submits a hidden/default host and creates an instance

- Severity: High.
- Impact: an operator is shown that no host qualifies, but Save creates the instance against blocked host `local` anyway. The visible form and authoritative submission disagree.
- Reproduction:
  1. Open `/admin/instances/new`.
  2. Choose Application.
  3. Open Host; observe `0 results` and no explanation.
  4. Choose runtime image `node-22`, enter name `visual-qa-20260826-invalid`, enter repository URL `not-a-url`, then Save.
- Expected: submission is refused because no eligible host was selected; the invalid URL should also be rejected.
- Actual: `/admin/instances/1/page/overview` was created and reports Host `local`, plus "Host local is not admitted for placement".
- Viewport/theme: 1440x900, light/auto.
- Evidence: browser view 3 revisions 13-25.
- Cleanup: in progress; the record cannot start and has no published port or measured disk.

#### F2 - Soft navigation leaves the document title at the list title

- Severity: Medium.
- Impact: browser history, tabs, screen readers, and orientation cues continue to announce `Sites` while the page is the `Starfleet Apex` record or Domains tab.
- Reproduction: click Starfleet Apex from `/admin/sites`, then click Domains.
- Expected: document title follows the record/page.
- Actual: URL advances to `/admin/sites/2` and `/admin/sites/2/page/domains`, but the document title remains `Sites`.
- Viewport/theme: 1440x900, light/auto.
- Evidence: E013 and browser tabs state.

#### F3 - SSR/direct-list microcopy keys leak before client settlement

- Severity: Medium.
- Impact: no-script, pre-hydration, assistive-technology, and slow-client users encounter implementation keys rather than labels.
- Reproduction: hard-load `/admin/dns-records` or inspect the initial Sites advanced-filter tree.
- Expected: `Add condition`, `Add group`, `Zone default (3600)`, and localized boolean labels.
- Actual initial semantic tree: `add_rule`, `add_group`, `ttl_zone_default`, and lower-case `yes`. Hydration later replaces at least some of them visually.
- Viewport/theme: 1440x900, light/auto.
- Evidence: `/admin/dns-records` document 2 revision 17; `/admin/sites` document 1 revision 1.

#### F4 - No wildcard certificate exists despite the testing brief

- Severity: Environment gap.
- Impact: arbitrary test subdomains resolve through wildcard DNS but cannot be tested over trusted TLS.
- Actual: two active Let's Encrypt certificates exist: `starfleet.life,www.starfleet.life` and `admin.starfleet.life`. No `*.starfleet.life` coverage is listed.
- URL: `/admin/certificates`.

#### F5 - List-search GET URL leaks the CSRF token

- Severity: Medium (security/privacy).
- Impact: the token enters browser history, copied URLs, server/access logs, analytics and potentially Referer headers. Search forms are safe GET navigation and do not need a CSRF credential.
- Reproduction: on `/admin/bans`, enter `visual-qa-20260826-no-match` in Search and press Enter.
- Expected: `?search=visual-qa-20260826-no-match...` without a token.
- Actual: URL begins `/admin/bans?csrf_token=...&sort=...&search=...`.
- Viewport/theme: 1440x900, light/auto at initial load; theme preference later dark does not affect behavior.
- Evidence: browser view 1 document 14 revision 30. The token value is intentionally omitted from this report.

#### F6 - Delete-with-data succeeds but soft navigation remains on a deleted record and logs a 404

- Impact: the destructive action completed, but the operator remains on stale record UI and receives no clear completion state. Console reports `Hawkeye navigation error: Server error: Not Found`.

- Actual: POST returned 200 and the record was deleted, but the UI remained at `/admin/instances/1/page/overview`; the follow-up XHR to that deleted route returned the not-found navigation payload. Direct navigation to the list confirmed count 0.
- Evidence: browser view 3 revisions 27-34; network requests 59-60; console lines 3-4.
