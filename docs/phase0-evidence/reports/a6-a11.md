**Issue: A11 — Maven consumers can still receive `-common` at runtime (Low/Design)**

**User-facing behavior changed:** a plain Maven `<dependency>` on any `-common` module used to receive the fold-neutral jar in default compile scope — on the compile AND runtime classpath beside `-client`/`-server`, recreating the duplicate-FQN wrong-fold state. Now the module publishes **no main jar**: the classes ride the `compile-only` CLASSIFIER, and (a welcome side effect of maven-publish) the generated POM carries `<packaging>pom</packaging>`. A default Maven dependency now fails loudly ("Could not find artifact ...jar"); deliberate Maven compile-time use must opt in via `<classifier>compile-only</classifier>`.

**Architectural responsibility changed:** none new — the change lives in the single canonical `publishCompileOnlyModule` helper, so all 16 `-common` publishers inherit it.

**Files changed:** `protoblast/protoblast-gradle-plugin/src/main/resources/be/elevenways/protoblast/gradle/publish-module.gradle` (`outgoing.artifact(jarTask) { classifier = 'compile-only' }` + AIDEV-NOTE stating the contract). Committed in protoblast `c76381a` (shared with A6 — same plugin, single publish).

**Tests added or changed:** none dedicated; verified through the full plugin functional suite (14 passed) and live chain republish.
